# 📦 归档区（Archive）

> **这是可追溯的历史知识库，不是日常开发依据。**

## 这个目录是什么

存放**已经完成、不再作为当前开发依据**的历史产物：干过的活、做过的决策、走过的坑。目的是让**后续接手项目的 AI / 人**能回溯"某个功能当初为什么这么做""这段奇怪代码的来龙去脉""某版本到底改了什么"。

## 使用约定（重要）

- ❌ **平时开发不读这里**。当前开发依据是 `.docs/api/`、`.docs/README.md`、`.docs/plans/`（活跃计划）、`.agent/`、`.rules/`。
- ✅ **只在以下场景查询**：
  - 排查一段"看起来很奇怪 / 故意为之"的代码，想知道历史原因
  - 了解某个已下线/重构功能的原始设计
  - 追溯某版本的完整变更与根因
  - 新 AI 接手项目、需要历史背景
- 查询方式：直接 `grep`/`codegraph` 关键词，或看下方索引。

## 目录结构

| 子目录 | 内容 |
|--------|------|
| `reports/` | 一次性完工报告、迁移检查单、框架实施报告等"做完即归档"的文档 |
| `plans/` | **已完全实现并发布**的功能计划（未完成/待办的计划留在 `.docs/plans/`） |
| `handoff/` | 已被对端接入、功能已上线的交接文档 |
| `sync-log/` | `SYNC_STATUS.md` 的历史信号日志 |

## 归档原则

1. **只归档"已完成"的东西**。进行中/待办的 plan、未接入的 handoff **不归档**，留在原位作为活跃依据。
2. 归档时在文件头部加 banner：`> 📦 已归档 YYYY-MM-DD · 仅供历史追溯，非当前开发依据`
3. 归档是**移动（git mv）**，不是删除 —— 保留 git 历史。
4. 每归档一批，在下方「归档索引」加一行。

## 触发方式

- **手动**：`/archive` skill（`.skills/shared/archive.md`）
- **自动**：发布流程（`release-workflow` skill）末尾自动归档本版本已完成的 plans/handoff
- 详见 `.rules/archive.md`
