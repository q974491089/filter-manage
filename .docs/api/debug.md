# 方案应用后的延迟回读

当前报告中的即时 GetDeviceGammaRamp 回读只说明系统层当时的曲线，不能证明画面持续采用它。

手动 apply_display_color_config 成功且实际后端为 standard 时，在活动调试会话中建立最终 LUT + generation 快照，约 250ms 与 1000ms 后只读回读。日志分类为 verify-delayed，包含方案、实际目标设备、代号、实际经过的毫秒数、全 RGB 高字节最大差与期望/实际 R 中间调。

整个回读持颜色门闩复核代号，后续滑块/方案/后端切换使旧任务不再读取；原调试会话结束后不得记录到新会话。回读失败保留为失败，不当成一致。不重新注册 ICC，不写颜色。NVIDIA 私有曲线后端不使用 GDI 回读判断其效果。

环境快照保留新接口给出的明确 hdr 状态；旧高级颜色位标注可能包含 HDR 与 SDR ACM，不再将其单独当作 HDR 证据。

更新于：2026-11-14。

## 方案短时补写日志（2026-11-15）

preset-settle 为方案应用的有限恢复流程日志，独立于 verify-delayed 只读诊断：约 250ms/750ms 记录曲线是否保持、偏差及是否补写。补写仅写最终 LUT，最大两次，操作代号或输出身份变化即取消；读取失败停止。verify-delayed 的 1000ms 读数发生在恢复预算结束后，可帮助区分初次重置、补写成功后保持、补写后再次重置。WCS 日志新增“关联相同，跳过注册/默认配置更新”“关联已更新”和查询/设置失败信息。所有读数仅表示系统层曲线，不等于用户屏幕效果验证。

## 当前输出 ICC 诊断修正（2026-11-15，v3 测试）

环境快照逐显示器打印 GDI 当前输出 ICC 的实际文件路径，读取失败明确记录。旧 Control Panel\Desktop\ICMProfile 字段及其缺省字符串改标为“旧桌面 ICC 注册表字段/缺省标签（不代表当前输出）”，不能作为实际配置证据。方案准备中 WCS 查询失败但 GDI 查询成功时记录两者，并仍允许相同有效配置跳过重复注册。错误日志包含查询作用域和 CPST_NONE，方便区分参数错误、缺少显式默认记录和输出查询失败。
